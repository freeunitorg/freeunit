# The structs and the macros that tools/perf/layout-check.sh compares.
# Each line is "<kind> <name>".
#
# shm:   Processes share the struct through shared memory.  A change to
#        its layout fails the check.  The router reads the requests
#        that libunit writes and the responses that it writes back, so
#        both directions are listed.
#        nxt_port_msg_t and nxt_port_mmap_msg_s are copied as bytes into
#        the data of a port queue item, and the reader decodes them with
#        its own layout.  pahole sees only the byte array there, so they
#        are listed on their own.  The same is true for the other
#        message payloads that libunit and unitd both decode: GET_MMAP
#        and GET_PORT (libunit to the router), NEW_PORT (the router to
#        libunit), and the WebSocket frame header in a shared buffer.
#        nxt_unit_sptr_u is the serialized pointer in the three
#        nxt_unit_*_s structs above: a union, listed on its own so that
#        a change to it fails by name, not only through --expand_types.
# const: A macro that sets the geometry of the shared memory.  pahole
#        does not see a macro, thus a program that is built with the
#        headers of the commit prints its value.  A change fails.  For
#        example, nxt_port_mmap_chunk_start() finds the data of a chunk
#        with PORT_MMAP_HEADER_SIZE and PORT_MMAP_CHUNK_SIZE.
# enum:  An enum constant in a header that "make install" copies.  A
#        module compiles the value into its code (NXT_UNIT_ERROR,
#        NXT_UNIT_HASH_CONTENT_LENGTH in src/python and src/java), so a
#        change fails, as for "const".  The program that prints the
#        "const" values prints these too, without the #ifdef that is
#        false for an enum constant.
#        The message numbers of the port protocol are here as well: each
#        _NXT_PORT_MSG_* value is the offset of a slot in
#        nxt_port_handlers_t, so inserting or reordering a slot renumbers
#        the wire protocol even when the build still passes.
#        tools/perf/layout-coverage.py reads src/nxt_port.h too, so a new
#        slot fails the check until it is listed.
# local: The struct is in the memory of one process.  A change to its
#        layout gives a warning.  Every struct defined in a header that
#        "make install" copies is listed, because a module is built
#        against those headers and lays the struct out itself:
#        tools/perf/layout-coverage.py fails when one is missing.
#
# If you remove an entry from this list, the check fails.
